# 面積事前確認のハーネス（屋根・外壁・内装）

写真から面積を読む機能が、実測にどれだけ当たっているかを測る。

```bash
node app/tools/harness-area/run.js            # truth/ の全件を回す
node app/tools/harness-area/run.js --dry      # APIを叩かず、正解データと設定だけ確認
node app/tools/harness-area/run.js --target=wall
node app/tools/harness-area/run.js --n=3      # 1件につき3回回して振れ幅も見る
```

## harness-roof との違い

`harness-roof` はプロンプトを `strategies.js` に**複製して持っている**。本番を直しても
ハーネスは古いプロンプトのまま回るので、乖離する。

こちらは **`main.ts` から出荷しているものをそのまま読む**（`shipped.js`）。

- プロンプト本文（target別の手順書ごと）
- モデル指定（`claude-opus-4-8` + adaptive thinking）
- レンジの倍率（屋根 ×0.65〜1.80 / 外壁・内装 ×0.55〜2.20）

本番を直せばハーネスも自動で追従する。逆に、`main.ts` の書き方を大きく変えると
`shipped.js` が読み取れずに落ちる。落ちたら `shipped.js` の正規表現を直すこと
（黙って古い値で回るより、落ちるほうが安全）。

## 正解データの入れ方

`truth/<好きな名前>.json` を1件につき1ファイル。

```json
{
  "target": "roof",
  "truthM2": 126,
  "file": "C:/Users/mitsu/.../写真.jpg",
  "comment": "戸建て住宅の屋根カバー工法。屋根面積を知りたい",
  "viewType": "oblique",
  "coversWhole": true,
  "note": "実測値の出どころ（見積書の数量／現場実測／図面の面積表 など）"
}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `target` | ★ | `roof` / `wall` / `floor` |
| `truthM2` | ★ | **実測値**。ここが正解になる。推定値を入れないこと |
| `file` | ★ | 写真のフルパス。`/` 区切りで書く |
| `comment` | ★ | 依頼文。本番と同じ条件で回すために必要 |
| `viewType` | | `oblique`（斜め・航空） / `onroof`（屋根の上） / `ground`（地上） / `drawing`（図面） |
| `coversWhole` | | 対象の輪郭が写真に収まっているか |
| `note` | | あとで自分が見て分かるように |

**`truthM2` には必ず実測値を入れる。** 図面の面積表・確定した見積書の数量・現場実測のいずれか。
「たぶんこれくらい」を入れると、ハーネス全体が嘘になる。

## ★最初に知っておくこと: 写真からの推定は再現しない

**同じ画像・同じプロンプト・同じモデルで2回回すと、答えが変わる。**

| 物件 | 1回目 | 2回目 | 倍率 |
|---|---|---|---|
| teigaku-asaka-68 | 111㎡ | 32㎡ | **0.29倍** |
| wkcover-slate-2000 | 1990㎡ | 3101㎡ | 1.56倍 |
| miracool-seppan-2200 | 1148㎡ | 726㎡ | 0.63倍 |

11件中3件が1.5倍以上ずれた。ばらつきの幅は ±54%（2026-09-02 計測）。
同じプロンプトの2回で、平均誤差が 53.5% と 61.2% に振れる。

**だから `--n=1` の結果でプロンプトの良し悪しを判定してはいけない。**
実際にこの罠を踏んだ。プロンプトを直して1回回し、「平均誤差が 36.8% → 62.8% に悪化した」
と判断したが、同じプロンプトで2回回したら 53.5% と 61.2% に振れた。
差はすべてノイズの範囲内で、プロンプトの効果は測れていなかった。

プロンプトを比べるときは `--n=3` 以上。較正係数を決め直すときも同じ。

## 測っているもの

**① 誤差** — 推定 ÷ 正解。正解が 68〜2200㎡ と2桁またぐので比で見る。

**② レンジの被覆率** ← いちばん大事

画面に出している「想定レンジ」が、正解を含んでいた割合。85%を下回ったら赤で警告する。

旧レンジ `×0.75〜×1.35` は、プロンプトに「必ずこの間に収まる」と書いてあるのに
**39% しか含んでいなかった**（2026-08-27 計測）。幅として機能していなかった。
ここが下がるということは、画面の主張が嘘になっているということ。

**③ 撮り方別の内訳**

屋根で測った結果、ここに大きな差が出た。

| 撮り方 | n | 平均誤差 |
|---|---|---|
| onroof（屋根の上） | 5 | **14.9%** |
| ground（地上） | 3 | 35.5% |
| oblique（斜め・航空） | 23 | 39.0% |

屋根の上から撮ると誤差が1/3になる。営業資料や利用案内に使える事実。

## いまの状態（2026-09-02）

| 対象 | 正解 | 状況 |
|---|---|---|
| 屋根 | 11件 | 測定済み。平均誤差35%前後・レンジ被覆91% |
| **外壁** | **0件** | **未収集。較正係数もレンジも未検証のまま出荷している** |
| **内装** | **0件** | **同上** |

外壁・内装は「屋根より精度が落ちるはず」という理屈だけで幅を広げてあり、
実測の裏づけがない。各10〜20件集めれば、屋根と同じ精度で語れるようになる。

## 分かっている事実（屋根11件・4モデル）

- 平均誤差は **31〜45%**。opus-4-8 / sonnet-5 / sonnet-4-6 で**大差ない**。
  モデルを変えても解決しない。写真に寸法の基準が無いことが原因。
- 系統的に**過少**に出る（生の推定は正解の 0.63〜0.87倍）。だから較正 ×1.50 が入っている。
  ただし較正で直るのは偏りだけで、**振れ幅は直らない**。
- **「屋根全体が写っている＝確定値」は成り立たない。**
  全体が写っている8件の平均誤差 34.9%、写っていない23件が 34.7%。差が無い。
  この事実にもとづき、写真は常に概算として扱うよう `main.ts` を変更した。
