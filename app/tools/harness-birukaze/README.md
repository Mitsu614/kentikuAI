# ビル風診断のハーネス

`docs/birukaze/index.html` の計算エンジンが、公表文献の報告と矛盾していないかを機械的に検査する。

```bash
node app/tools/harness-birukaze/run.js         # 不変条件 + 分布 + 感度分析
node app/tools/harness-birukaze/run.js --sens  # 感度分析だけ
node app/tools/harness-birukaze/run.js --json  # JSONで吐く
```

不変条件がひとつでも落ちると終了コード 1。結果は `harness-result.json` に残る。

## これで測れること・測れないこと

**測れない：実測に何%で当たるか。**

風洞実験の実測値を正解として突き合わせたかったが、入手できなかった。AIJ（日本建築学会）が
CFD検証用のベンチマーク（Case A〜G）を公開しているものの、数値が論文の図の中にあり、
表として取り出せない。PDFからテキストは抽出できたが、データは図版だった。

**測れること：文献の傾向と矛盾していないか。**

`harness-electrical`（電気設備）と同じ「自己整合を測る」方式にした。公表文献が報告している
**定性的な関係**——順序・単調性・値の範囲——を不変条件に置き、1800ケースを掃いて検査する。

係数をいじったら回し直す。「Tsang らは幅のほうが効くと言っているのに、逆になった」といった
退行がその場で分かる。

## このハーネスが見つけた実害

**増加率だけを見ていると、判定を動かす入力を見落とす。**

最初は増加率の振れ幅だけを測っていた。それだと以下を取りこぼす。

| 入力 | 増加率の振れ | 村上ランクの振れ |
|---|---|---|
| 粗度区分（4択） | 11.7% | **3段階**（1→1→3→4） |
| 建蔽率 ±20% | **0.0%** | **2段階**（4→3→2） |
| 地域（6択） | **0.0%** | **2段階** |
| 足元の形 | 25.0% | 1段階 |
| 高さ ±20% | 2.5% | 0段階 |

建蔽率と地域は増加率を1%も動かさない。増加率ではなく、風速比と気象統計の側から効くためだ。
**しかも建蔽率は「わからない」で飛ばせる任意項目なのに、判定を2段階動かす。**

掃いた400ケースのうち **94%** で、粗度区分を1段・建蔽率を±10%振るとランクが変わった。
つまりほぼ全ての診断で、点推定だけを出すのは持っていない精度を主張していることになる。

**対応：** `rankBand()` を追加し、結果カードにランクの幅を併記するようにした
（「ランク3　幅 2〜4」）。点推定の精度は上げられないが、不確かさを隠さないことはできる。

## つまみ

較正対象は `docs/birukaze/index.html` の `TUNING` に集約してある。
`model.js` の `load({gain: 0.7})` のように差し替えて回せる。

エンジンはコピーせず、**出荷している HTML から毎回切り出して読む**。
複製を置くと本番を直したときに片方だけ古くなるため。
